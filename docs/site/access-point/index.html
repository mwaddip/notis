Notis / access point

A box as an access point to the mesh.

A box running a Notis node can broadcast a Wi-Fi network that carries the notice board and nothing else. A phone on that network and no other reads, posts and likes through the box's node, which carries the writes out over its own connection. Where the internet is censored or absent, the board still reaches whoever is near a box.

What it is for

The access point is a second Wi-Fi network on a box that already runs a Notis node. A phone joining it reaches the box's node and nothing else: every name lookup is refused at once, and a packet for any other address is refused within seconds. The box keeps its own connection — a router over Wi-Fi, or none — and uses it to carry the mesh on the phone's behalf. Nothing on the access point reaches the internet.

The name a joiner sees is the one you choose for the network, and if you set no password anyone nearby can join. Notis's own traffic is encrypted either way — the password decides who joins the network, not who can read what Notis carries.

What you need

A Raspberry Pi 4B with the node installed from the project's .deb and the dagsocial-node service running. The Pi's built-in Wi-Fi is the one radio the tool knows today; it carries a client link and an access point at once, on one channel. The box's own connection to a router is optional — with one, the access point runs on the router's channel; with none, the tool picks a 2.4 GHz channel of its own.

The tool

The .deb installs /usr/bin/dagsocial-access-point. The package never runs it, so a box that never runs it is unchanged by the package. It runs as root, with three commands:

sudo dagsocial-access-point setup
sudo dagsocial-access-point status
sudo dagsocial-access-point remove

setup takes two options:

  • --name <network name> — the name a joiner sees. Default: Notis, up to 32 bytes. The name is visible to anyone nearby.
  • --password <8–63 characters> — a WPA2 password. Default: an open network, which anyone nearby can join.
sudo dagsocial-access-point setup --name "Reading Room" --password "a long passphrase"

status reads each of setup's changes back from the box. remove undoes them in reverse, and warns first that stopping the access point drops the box's own Wi-Fi for a few seconds — one radio carries both. A setup on a box already set up changes nothing.

What setup does, step by step

Each step setup takes is one an operator can take by hand. The commands are what the tool runs, in order; the files are what it writes. Every change is written to /etc/dagsocial/access-point/record.json as it is made, so remove undoes exactly what was done, and a setup that stopped half way is undone as far as it went.

1. The node's mesh role

Add the mesh role and a WebRTC-direct listen to /etc/dagsocial/node.env, so the node listens on the access point's interface. A node already set to private with a WebRTC-direct listen keeps what it has; a node set to public is refused — a public node lists no local addresses, and discovery through an access point would dial nothing.

MESH_ROLE=private
MESH_LISTEN=/ip4/0.0.0.0/udp/9733/webrtc-direct

2. The radio

Check that the radio carries a client link and an access point in one interface combination. A radio that does not is refused, saying so.

iw list

3. The channel

One radio offers one channel to both links. With an uplink on an ordinary channel, the access point runs on that channel. With an uplink on a channel flagged for radar detection — where no access point starts — the uplink is moved to the 2.4 GHz band where its network offers one there; with no 2.4 GHz band on that network, setup stops and says why. With no uplink at all, the tool picks a 2.4 GHz channel no radar flag holds.

When the uplink is moved, the tool reads the profile's prior band first (so remove restores it), then rewrites it:

nmcli -g 802-11-wireless.band con show <uplink-profile>
nmcli con modify <uplink-profile> 802-11-wireless.band bg
nmcli con up <uplink-profile>

4. The uap0 interface unit

Write a systemd unit that makes the uap0 access-point interface at every boot, before NetworkManager starts — NetworkManager does not create a virtual interface itself. The unit is /etc/systemd/system/dagsocial-ap-iface.service; its ExecStart runs iw dev <uplink> interface add uap0 type __ap where there is an uplink, and iw phy <phy> interface add uap0 type __ap where there is none. Enable and start it:

systemctl daemon-reload
systemctl enable dagsocial-ap-iface.service
systemctl start dagsocial-ap-iface.service

5. The NetworkManager profile

Add a NetworkManager profile named dagsocial-ap that runs the access point on uap0 at 10.78.79.1/24 — the address every box answers at, outside the ranges routers and hotspots take by default; where the box's router uses 10.78.79.0/24 itself, setup stops before its first change and says why — connects at boot, and carries the name and the password you chose. The band and channel are the ones step 3 picked:

nmcli con add type wifi ifname uap0 con-name dagsocial-ap \
  autoconnect yes ssid "Notis" \
  802-11-wireless.mode ap \
  802-11-wireless.band bg \
  802-11-wireless.channel 1 \
  ipv4.method manual ipv4.addresses 10.78.79.1/24 \
  ipv6.method disabled
nmcli con up dagsocial-ap

NetworkManager registers the new uap0 on its own time, so wait until nmcli dev shows it as disconnected — listed is not yet ready — before nmcli con up; at boot the interface unit runs before NetworkManager starts, and the profile comes up by itself.

Where you set a password, the add command carries two more fields, wifi-sec.key-mgmt wpa-psk and wifi-sec.psk <password>. NetworkManager's ipv4.method shared is never used: it forwards to the internet.

6. Addresses, and no names

Write a dnsmasq configuration and a systemd unit for a dnsmasq instance bound to uap0 alone. It hands out addresses between 10.78.79.10 and 10.78.79.254, names the box as the router and the DNS server, and refuses every name at once — never a timeout. The extension reaches the box by its address alone. The files are /etc/dagsocial/access-point/dnsmasq.conf and /etc/systemd/system/dagsocial-ap-dnsmasq.service. Enable and start it:

systemctl daemon-reload
systemctl enable dagsocial-ap-dnsmasq.service
systemctl start dagsocial-ap-dnsmasq.service

7. Nothing past the box

Write an nftables ruleset and a systemd unit for one table, inet dagsocial_ap, that accepts from uap0 DHCP, DNS, port 80 at 10.78.79.1 — redirected to the node's HTTP port — and the node's WebRTC-direct UDP port, and refuses the rest. The box forwards nothing: with forwarding off, as it is on Debian unless something turns it on, the kernel answers a packet for any other address as unreachable, and a device on the access point learns within seconds that nothing beyond it answers. The table also refuses every forwarded packet, should anything turn forwarding on. The files are /etc/dagsocial/access-point/firewall.nft and /etc/systemd/system/dagsocial-ap-firewall.service. Enable and start it:

systemctl daemon-reload
systemctl enable dagsocial-ap-firewall.service
systemctl start dagsocial-ap-firewall.service

8. Restart the node

Restart the node so it reads the new node.env:

systemctl restart dagsocial-node

What to expect

Stopping the access point drops the box's own Wi-Fi for a few seconds: one radio carries both links, and the client link reconnects on its own after the access point ends. remove says so before it starts. An upgrade of the .deb keeps the access point: the tool's files live outside the package's tree, and node.env is the package's conffile, which the package keeps across upgrades.

The box's own Wi-Fi is slower on 2.4 GHz than on 5 GHz. Where the box's router channel was flagged for radar detection, step 3 moved the uplink to 2.4 GHz — remove moves it back. Where netplan writes the box's Wi-Fi profile, NetworkManager adds a timestamp to the profile's netplan file whenever the profile changes: after remove the profile's settings are as they were, and the file carries that timestamp.

For a reader on a phone

Join the network by its name. On Android a notification says the network has no internet access: tap it, tick Don’t ask again for this network and choose Yes to stay connected. Until you do, apps cannot use the network, and a phone that knows another network with internet in range switches back to it within a minute.

Open the extension. It reads the box's node on its own: a check that reaches no node on the regular seed list reads the box's identity at http://10.78.79.1/mesh/identity and adds the node it names; the feed reads searching for a connection… while it looks, and loads by itself once the box answers. The extension remembers the box, so a reload on the access point dials it at once. The settings window's debug row shows the found node, marked found on this network, beside how it is reached.
